## 배경 · 목적

**1. 반복 접수된 VOC** "아하오호 화면 보기가 작아서 아이 화면을 보여주기 어렵다"는 요청이 교사로부터 반복 접수됨

**2. 기본 배율에서 UI가 잘림** 기준 기기(LG 그램 14 / 1280×800 / 배율 100%)에서 팝업이 화면을 넘어가 하단 버튼이 잘림. 원인은 세로형 앱 화면을 **모달 padding → 헤더·탭 → 축소된 박스 안의 세로 카드**로 3중 중첩해 넣은 구조이며, 특정 챌린지의 문제가 아님.

**3. 현장에서 관찰된 우회 사용** 교사들이 제품을 못 쓰는 것이 아니라, **각자 우회 방법을 찾아 쓰고 있음**이 관찰됨.

| 우회 방식 | 무엇을 말해주는가 |
|---|---|
| 브라우저 배율을 90%로 낮춤 | 기본 배율(100%)에서 UI가 잘려 정상 사용이 안 됨 |
| F11로 브라우저 전체화면 진입 | 팝업이 화면을 제대로 쓰지 못함 |

**4. 문제 해석** 팝업 크기를 조금 키우는 방식으로는 해상도가 바뀌면 다시 잘리므로, **높이 우선 영역 맞춤**으로 바꿔 어느 해상도·배율에서도 잘림이 구조적으로 발생하지 않게 해야 함.

**5. 목적** 우회 조작 없이 **기본 상태에서 아이가 보는 앱 화면을 최대 크기로 보여주고, 필요하면 제품 안에서 더 확대**할 수 있게 함. 단, 교사가 아이에게 설명할 수 있어야 하므로 **앱 화면 구성 자체는 바꾸지 않음**. 상위 맥락은 `1pager_클래스_정식출시.md`의 교사 여정 4단계 중 **③ 수업 중** 단계 병목 제거.

**6. 완료 기준** 동일 유형 VOC 재접수 0건 + 배율 축소·F11 **어느 우회도 필요하지 않은 상태** (아래 인수 기준으로 판정)

## 레이아웃 기준

기준 해상도 **1280×800** (LG 그램 14 / 1920×1200 @150%), 브라우저 배율 100%. 실측값은 이 기준의 프로토타입에서 측정한 값임.

### 아하오호 화면 보기 탭

| 영역 | 크기 | 구성 |
|---|---|---|
| 상단 바 | 높이 **56px** 고정 | 공통 1 챌린지명 · 공통 3 구분탭 · 공통 2 모달 닫기 |
| 앱 화면 스테이지 | 나머지 전체 (**1016×744**). 좌우 여백 64px(공통 8 화살표 자리), 상하 여백 20px | 공통 5 앱 화면 카드 · 공통 6 확대 · 공통 7 조작 안내 |
| 우측 진행 단계 레일 | 폭 **264px** 고정 | 공통 4 진행 단계 |

**앱 화면 카드 규칙** — 세로 4:5 비율을 유지한 채 **높이를 스테이지에 맞추고**(`height:100%`), 폭은 비율에 따라 결정됨. 폭이 스테이지보다 넓어지는 경우에만 폭 기준으로 축소.

- 카드 높이 = `100dvh − 56 − 40` → 800px에서 **704px** (폭 563px)
- 카드 밖 컨트롤(가이드 8)이 있는 화면은 44px을 뺀 **660px** (폭 528px)
- 현행 팝업 대비 앱 화면이 차지하는 높이가 커지고, **화면이 작아지면 카드가 통째로 줄어들 뿐 잘리지 않음**

### 수업 정보 탭

| 영역 | 크기 | 구성 |
|---|---|---|
| 좌측 고정 열 | 폭 **268px**, 스크롤되지 않음 | 1 활동 키워드 · 2 성취 역량 · 3 카테고리 · 4 난이도 · 5 준비물 |
| 우측 본문 열 | 나머지 (**982×744**), 이 영역만 세로 스크롤 | 6 챌린지 설명 · 7 활동 목표 · 8 교과 성취 기준 · 9·10 교육자 참고 자료 · 11 기타 참고 사항 · 12 추천 챌린지 |

- 이 탭에는 **진행 단계 레일을 출력하지 않음** → 문서가 화면 폭(1280px)을 전부 사용
- 본문 열 전체 높이 1397px / 가용 높이 744px → 약 0.9화면 분량의 스크롤

정책 : 좌측 열은 수업 준비 시 계속 참조하는 메타 정보이므로 스크롤에서 제외해 항상 보이게 함(현행 방식 유지)

## 번호 표기 화면 안내

번호 표기 캡쳐는 **각 화면 섹션 첫머리**에 있음. 단계와 탭이 나뉘어 있어 한 화면에 모든 번호를 담을 수 없으므로 프레임을 나눠 캡쳐함.

- 모두 1280×800 기준 2배 캡쳐. 배지 색은 **빨강 = 유지·변경 / 파랑 = 핵심 변경 / 초록 = 신규**
- **각 캡쳐에는 그 화면의 번호만 표기**함. 모든 화면에 걸치는 `공통 1~8`은 별도 캡쳐로 분리
- 수업 정보는 열이 좁아 번호가 겹치므로 반대쪽 열을 비워 캡쳐했고, 레이아웃·위치는 실제와 동일함
- 재생성이 필요하면 `번호 표기 화면/_make_callouts.py` 실행 (번호 위치는 레이아웃에 맞춰 자동 계산)

# 공통 (모든 화면)

![공통 번호 표기](번호%20표기%20화면/callout_공통.png)

> 개요 화면을 기준으로 캡쳐함. 수업 정보 탭에서는 공통 4·8이 미출력되고 공통 7은 `ESC 닫기`만 노출됨.

## 공통 1) 챌린지명 (challenge_title)

전체 화면 상단 바 좌측으로 이동. 출력 규칙(airtable '액티비티 타이틀', 최대 24자)은 기존과 동일.

## 공통 2) 모달 닫기 (close)

상단 바 **우측 끝**으로 이동. `ESC` 키로도 닫힘.

예외 처리 : 수업 정보 탭의 추천 챌린지(12)로 다른 챌린지 모달이 겹쳐 열린 상태에서는, 이 닫기 버튼과 `ESC` **모두 겹친 모달만 닫고 이전 챌린지 모달을 그대로 남김** (한 번에 한 단씩 닫힘)

## 공통 3) 구분탭 (tab)

상단 바 중앙, 챌린지명 오른쪽으로 이동. 구분(아하오호 화면 보기 / 수업 정보)과 동작은 기존과 동일.

정책 : 탭 전환 시 확대 배율은 1배로 초기화되고, 화면 보기 탭으로 돌아오면 마지막에 보던 단계가 유지됨

## 공통 4) 진행 단계 (step_nav) — 규칙 변경

기존 기획서의 **상단 브레드 스크럼**(`개요 > 가이드 자세히 보기 > 기록하기 > 프로젝트 돌아보기`)을 **우측 264px 레일**로 옮김.

- 단계 구성은 기존과 동일한 4단계. 현재 단계는 볼드 + 원형 강조, 지난 단계는 체크 표시
- 단계 클릭 시 해당 화면으로 바로 이동(기존 브레드 스크럼과 동일)

정책 : 브레드 스크럼은 가로 폭을 쓰면서 앱 화면에 줄 높이를 빼앗음. 전체 화면에서는 세로 공간이 카드 크기를 직접 결정하므로, 남는 가로 공간(우측)으로 옮겨 카드 높이를 확보. 단계별 진행 상태를 세로로 나열하면 교사가 아이의 진행 위치를 설명하기도 쉬움
예외 처리 : 수업 정보 탭에서는 미출력(단계 흐름과 무관한 화면)

## 공통 5) 앱 화면 카드 (app_frame) — 핵심 변경

고정 크기 팝업 안의 축소된 박스 → **높이 우선 영역 맞춤(contain-fit)** 으로 변경. 상세 수치는 위 레이아웃 기준 참조.

- 세로 4:5 비율 유지, 높이를 스테이지에 맞춤
- 창 크기가 줄어들면 **카드가 통째로 축소**되며, 어느 크기에서도 잘리지 않음
- 카드 안의 앱 화면 구성(요소 순서·배치)은 변경하지 않음

예외 처리 : 창 폭이 매우 좁아 4:5 카드의 폭이 스테이지를 넘어가면 폭 기준으로 축소(높이에 여백이 생김)

## 공통 6) 확대 (zoom) — 신규

앱 화면 카드를 커서 위치 기준으로 확대·축소.

- 입력 : 마우스 휠 또는 트랙패드 핀치(`ctrl + wheel`). **호버만으로는 동작하지 않음**
- 배율 : 1배 ~ 3배 (1배 미만 축소 없음)
- 이동 : 확대 상태에서 드래그(팬). 커서는 `grab`/`grabbing`
- 초기화 : 더블클릭, 단계·탭 전환, 모달 닫기
- 확대 대상은 **앱 화면 카드로 한정** — 공통 4 진행 단계, 공통 7 조작 안내, 공통 8 화살표, 가이드 8 페이지 이동은 함께 확대되지 않음

예외 처리 : 확대 상태에서 앱 화면 버튼(시작하기 등)을 클릭해도 드래그로 오인하지 않아야 함 / 개요의 2-1 화살표는 앱 UI이므로 카드와 함께 확대됨

## 공통 7) 조작 안내 (controls_hint) — 신규

스테이지 **좌하단**에 조작 방법을 아이콘과 함께 상시 노출. **항목별로 한 줄씩 세로 나열**. 확대 시 함께 커지지 않음.

| 순서 | 아이콘 | 문구 | 노출 탭 |
|---|---|---|---|
| 1 | 🔍 돋보기+ | 휠·핀치로 확대 | 화면 보기 |
| 2 | ✥ 사방 화살표 | 드래그로 이동 | 화면 보기 |
| 3 | 커서 | 더블클릭하면 원래 크기 | 화면 보기 |
| 4 | `←` `→` 키캡 | 화면 넘기기 | 화면 보기 |
| 5 | `ESC` 키캡 | 닫기 | 화면 보기 · 수업 정보 |

- 반투명 딤 배경의 둥근 사각 박스, 항목 간 8px 간격의 **세로 목록**. 수업 정보 탭에서는 밝은 톤으로 전환

정책 : 확대와 키보드 이동은 화면에 단서가 없으면 발견할 수 없는 기능이고, 교사가 수업 중에 사용법을 찾아볼 여유가 없으므로 상시 노출로 둠. 수업 정보 탭은 확대가 없고 스크롤은 학습이 필요 없어 `ESC 닫기`만 남김
예외 처리 : [작성 필요 — 문구 UX 라이팅 확정 / 아이콘 최종 에셋 확정]

## 공통 8) 좌우 화면 이동 (screen_nav) — 신규

스테이지 좌우에 44px 원형 화살표. 키보드 `←` `→` 로도 이동.

**단계만 건너뛰지 않고 단계 안의 페이지까지 순서대로 이동**함.

```
개요 썸네일 → Pick 1 → Pick 2 → Pick 3
→ 가이드 1/3 → 2/3 → 3/3(마무리)
→ 기록하기 → 프로젝트 돌아보기
```

- 첫 지점에서 `이전`, 마지막 지점에서 `다음`은 비활성 처리
- 가이드에서 뒤로 가면 개요의 **마지막 Pick 슬라이드**로 되돌아감
- 수업 정보 탭에서는 미출력(키보드 `←` `→` 도 동작하지 않음)

정책 : 교사가 아이 화면을 처음부터 끝까지 훑는 것이 이 화면에서 가장 빈번한 조작임. 단계 단위로만 이동하면 가이드 중간 페이지를 건너뛰게 되므로 페이지까지 순서대로 지나가게 함. 특정 단계로 바로 가는 것은 공통 4 진행 단계가 담당
예외 처리 : 화면 이동 시 확대 배율은 1배로 초기화

# 개요

![개요 번호 표기](번호%20표기%20화면/callout_개요.png)

## 개요 1·2) 썸네일·Pick 이미지 영역 (thumbnail)

썸네일(`contents.humbnail`)과 아하's Pick 이미지가 **같은 영역을 슬라이드로 공유**함. 출력 비율은 기존과 동일.

## 개요 2-1) 아하's Pick 슬라이드 이동 화살표 (pick_nav)

기존 기획서 규칙 그대로 구현. **이미지 안 좌우**에 배치.

- 노출 조건 : 아하's Pick이 **1개 이상 지정된 챌린지 (피처드 풀 전체 중 최대 3개를 랜덤 순서로 노출)**
- 클릭 시 다음 화면으로 전환 + **아하의 설명글(개요 6)도 맞춰 자동 전환**
- 첫 번째 슬라이드(썸네일)에서는 **우측 화살표만**, 한 번 넘기면 **좌우 모두**, 마지막 슬라이드에서는 **좌측 화살표만** 노출

정책 : 이 화살표는 아이가 앱에서 실제로 누르는 앱 UI이므로 앱과 동일하게 이미지 안에 두고, 카드와 함께 확대됨. 교사가 시안을 넘겨보는 조작(가이드 8, 공통 8)과는 성격이 다름
예외 처리 : Pick이 0개면 화살표·인디케이터 모두 미출력

## 개요 2-2) 슬라이드 인디케이터 (pick_indicator) — 신규

이미지 **하단 중앙**에 현재 슬라이드 위치 표시. 노출 조건은 2-1과 동일. 앱에도 동일한 인디케이터가 있음.

## 개요 2-3) 프로젝트 게시자 표기 (pick_author) — 신규

Pick 이미지 **좌상단**에 그 프로젝트를 게시한 아이의 프로필 이미지 + 닉네임을 오버레이(앱과 동일). 썸네일 슬라이드에서는 미출력

## 개요 6) 소개 문구 (essential_info)

`essentialInfo`를 말풍선에 출력. 출력 규칙은 기존과 동일하되, **슬라이드에 따라 문구가 달라짐**.

| 슬라이드 | 말풍선 내용 |
|---|---|
| 챌린지 썸네일 | `essentialInfo` → 개요 7 탭에 따라 필수정보리스트로 교체 |
| 아하's Pick | **`다른 친구들은 어떻게 했을까?` 고정** (기존 기획서 2-1의 자동 전환 규칙) |

## 개요 7) 아하 캐릭터 (aha_character)

**탭할 때마다 필수정보리스트 데이터가 말풍선에 순차로 노출됨** (기존과 동일). 마지막 항목 다음에는 처음 문구로 돌아옴.

- **아하's Pick 슬라이드에서는 탭해도 반응하지 않음** — 말풍선은 `다른 친구들은 어떻게 했을까?`로 고정
- 썸네일 슬라이드로 돌아오면 다시 반응하며, 말풍선은 첫 문구부터 시작

## 개요 8) 시작하기 버튼 (start)

**클릭 시 해당 챌린지 경로의 다음 단계로 이동** (가이드 자세히 보기)

## 개요 9) 활동재료 버튼 (materials)

단계 진행과 무관한 앱 전용 기능이므로, 클릭 시 토스트 출력 : **`아하오호 앱에서만 사용할 수 있는 기능입니다.`** (기존과 동일)

정책 : 같은 토스트가 붙는 대상은 **단계 진행 버튼이 아닌 조작** — 활동재료, 기록하기 화면의 챌린지 선택·공개 범위 등. 단계를 넘기는 버튼(개요 8, 가이드 7, 기록하기 4, 돌아보기 3)은 실제로 화면이 이동해야 함

# 가이드 자세히 보기

![가이드 자세히 보기 번호 표기](번호%20표기%20화면/callout_가이드_자세히보기.png)

## 가이드 1) 가이드 페이지네이션 (guide_page)

`현재/전체` 형식으로 카드 상단에 표시(`1/3`). 진행 바와 함께 출력. 출력 규칙은 기존과 동일.

## 가이드 2) 가이드 이미지/영상 (guide_media)

`mediaUrl` 출력. **가로가 긴 이미지와 세로가 긴 이미지가 혼재**하므로, 이미지 박스 안에서 원본 비율 그대로 영역 맞춤(contain). 박스 크기는 고정되고 이미지만 맞춰짐.

- 1280×800에서 이미지 박스 **496×508px**
- 원본 해상도보다 크게 확대하지 않음 — 더 크게 볼 때는 공통 6 확대를 사용

예외 처리 : `mediaUrl` 로딩 실패 시 기본 플레이스홀더 표시(기존 규칙 유지)

## 가이드 3) 사운드 on/off (guide_sound) — 이슈 수정 필요

노출 조건과 기본값은 기존과 동일 : **`sound=true`인 가이드 페이지에만 버튼 출력**, 기본값 **off**.

- 위치 : 가이드 미디어 **좌상단 안쪽** (미디어 박스가 아니라 **미디어 자체**를 기준으로 함 — 페이지마다 이미지 비율이 달라 박스 기준으로 잡으면 여백에 떠 보임)
- 상태 표시 : 반투명 어두운 원형 버튼에 **아이콘만 바뀜** — off는 음소거 스피커, on은 스피커. 배경색·강조색으로 구분하지 않음

**현행 이슈** — 페이지를 넘겨도 **이전 페이지 가이드의 사운드가 계속 재생됨**. 페이지를 연속으로 넘기면 소리가 겹쳐 들림

| 상황 | 동작 |
|---|---|
| 페이지 진입 (기본) | off — 재생하지 않음 |
| on으로 전환 | 현재 페이지의 사운드 재생 |
| **페이지 이동** | **이전 페이지 사운드 즉시 정지**. on 상태는 유지되므로 이동한 페이지의 사운드가 이어서 재생됨 |
| off로 전환 | 재생 정지. off 상태도 페이지를 넘겨도 유지됨 |
| `sound=false`인 페이지 | 버튼 미출력·재생 없음. on 상태 자체는 유지되어, 사운드가 있는 페이지로 돌아가면 다시 재생됨 |

- on/off는 **사용자가 다시 바꿀 때까지 유지되는 상태**이고, 재생은 **현재 보고 있는 페이지 것만** 이루어짐
- 앱 UI이므로 카드와 함께 확대됨(개요 2-1과 동일)

정책 : on/off를 페이지마다 초기화하면 교사가 페이지를 넘길 때마다 다시 켜야 하므로 상태는 유지함. 다만 재생 자체가 페이지에 종속되지 않으면 소리가 겹쳐 현행 이슈가 발생하므로, **상태는 유지 / 재생은 현재 페이지 한정**으로 분리함
예외 처리 : 가이드 단계를 벗어나거나(기록하기·돌아보기·개요) 수업 정보 탭으로 전환하거나 모달을 닫으면 재생 정지 / 모달을 새로 열면 off로 초기화

## 가이드 4) 가이드 설명 (guide_text)

`guide` 출력. 출력 규칙은 기존과 동일하되 **최대 85자가 3줄까지 들어갈 높이를 미리 확보**하고, 그만큼 이미지가 양보하도록 함.

정책 : 한 줄만 확보하면 긴 설명에서 텍스트가 잘리거나 이미지를 밀어냄. 세로로 긴 이미지일 때 특히 문제가 되므로, 최대 글자 수 기준으로 영역을 먼저 확보해 페이지를 넘겨도 이미지 크기가 흔들리지 않게 함

## 가이드 5·6·7) 마지막 페이지

![가이드 마지막 페이지 번호 표기](번호%20표기%20화면/callout_가이드_마무리.png)

마지막 페이지는 **이미지가 없는 별도 페이지**로, 위에서부터 업로드 안내 문구(말풍선) → 오호 캐릭터 애니메이션 → 하단 전체 폭 `기록하기` 버튼 순으로 배치. 각 항목의 출력 규칙은 기존과 동일.

## 가이드 8) 페이지 이동 컨트롤 (guide_nav) — 위치 변경

가이드 페이지 이동(`◀ ▶`)을 앱 화면 카드 **바깥 하단**에 배치. 끝 페이지에서는 해당 방향 화살표를 미노출.

정책 : 카드 안에 두면 앱 화면 구성을 바꾸게 되고 확대 시 함께 커져 조작을 방해함. 이 컨트롤이 있는 화면은 카드 높이에서 44px을 뺌
예외 처리 : 이 컨트롤은 해당 단계 안에서만 이동하고, 단계를 넘어가는 이동은 공통 8이 담당

## 수업 정보 12) 추천 챌린지 — 배치·동작 변경

![참고 자료·추천 챌린지 번호 표기](번호%20표기%20화면/callout_수업정보_참고자료_추천.png)

- 카드는 **정방형(1:1) 썸네일**, 가로 스크롤 없이 **줄바꿈**으로 배치. 1280×800에서 한 줄 5장
- **카드 클릭 시 해당 챌린지의 챌린지 상세 보기 모달이 위에 겹쳐 열림**. 겹친 모달은 **일반 모달과 완전히 동일한 전체 화면**이며(들여쓰기·딤 처리 없음), 화면 보기 탭의 개요부터 시작
- **상위 챌린지의 하위 계층으로 표시하지 않음** — 상단 바에 경로(브레드 스크럼)나 이전 챌린지명을 표기하지 않고, 상단 바 구성도 일반 모달과 같음
- **`✕` 닫기 · `ESC` 모두 위에 겹친 모달만 닫고, 이전에 띄운 챌린지 모달을 그대로 남김.** 전체를 닫으려면 반복해서 닫으면 됨
- 여러 단 중첩 가능 (추천 챌린지에서 다시 추천 챌린지를 눌러도 계속 쌓임)

정책 : 현재 보던 챌린지를 잃지 않고 열었다 닫을 수 있어야 하므로 닫기는 전체 종료가 아니라 **한 단 복귀**로 동작함. 또 추천 챌린지는 현재 챌린지의 하위 항목이 아니라 **동등한 다른 챌린지**이므로, 경로로 표기하면 종속 관계로 읽히고 중첩 시 상단 바를 잠식하므로 계층 표기를 두지 않음
예외 처리 : 겹친 모달의 수업 정보는 해당 챌린지의 데이터를 새로 조회함 / 프로토타입에서는 제목·카테고리·썸네일만 교체되고 수업 정보 내용은 예시 데이터가 그대로임

## 인수 기준 (QA 확인 항목)

1. 기준 해상도 1280×800 · 브라우저 배율 **100%** · F11 미사용 상태에서 모든 UI가 잘림 없이 표시
2. 챌린지 썸네일 클릭 시 새 창·새 탭이 열리지 않음
3. 창 크기를 1280×800에서 더 줄여도 앱 화면 카드가 잘리지 않고 비율을 유지한 채 축소됨
4. 4개 단계 전부에서 카드 하단 버튼(시작하기·기록하기·완료)이 잘리지 않고 보임
5. 가이드 설명이 85자일 때 3줄이 모두 표시되고, 페이지를 넘겨도 이미지 박스 크기가 변하지 않음
6. 가로가 긴 이미지·세로가 긴 이미지 두 케이스에서 이미지가 박스에 맞춰 표시되고 원본 해상도를 초과해 확대되지 않음
7. 확대 3배 상태에서 공통 4·7·8, 가이드 8의 크기·위치가 변하지 않고, 개요 2-1 화살표는 카드와 함께 확대됨
8. 단계·탭 전환 시 확대 배율이 1배로 초기화됨
