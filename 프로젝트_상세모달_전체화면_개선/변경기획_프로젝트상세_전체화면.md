## 배경 · 목적

**1. 반복 접수된 VOC**
"프로젝트 상세에서 이미지·영상이 작게 보인다"는 요청이 교사로부터 반복 접수됨. 개별 응대로 처리해 왔으나 같은 유형이 계속 들어오는 상태.

**2. 현장에서 관찰된 우회 사용**
교사들이 제품을 못 쓰는 것이 아니라, **각자 우회 방법을 찾아 쓰고 있음**이 관찰됨.

| 우회 방식 | 무엇을 말해주는가 |
|---|---|
| 브라우저 배율을 90%로 낮춤 | 기본 배율(100%)에서 UI가 잘려 정상 사용이 안 됨 |
| F11로 브라우저 전체화면 진입 | 모달이 화면을 제대로 쓰지 못함 |
| **화면을 캡쳐해 이미지 뷰어에서 확대** | **제품 안에서 해결이 안 되어 제품 밖으로 나감** |

**3. 문제 해석**
세 번째(캡쳐 후 확대)가 가장 중요한 신호. 확대 수단이 없어 교사가 **아하오호를 벗어나 OS 이미지 뷰어로 이동**한 것이며, 이는 도구가 본래 목적(아이 작품을 함께 보기)을 달성하지 못했다는 뜻. 부가적으로 아이 작품·닉네임이 담긴 화면이 **교사 개인 기기에 관리되지 않는 사본**으로 남는 문제도 발생.

**4. 목적**
우회 조작 없이 **기본 상태에서 아이 작품을 최대 크기로 보고, 필요하면 제품 안에서 더 확대**할 수 있게 함. 상위 맥락은 `1pager_클래스_정식출시.md`의 교사 여정 4단계 중 **③ 수업 중** 단계 병목 제거.

**5. 완료 기준**
동일 유형 VOC 재접수 0건 + 배율 축소·F11·화면 캡쳐 중 **어느 우회도 필요하지 않은 상태** (아래 인수 기준으로 판정)

## 레이아웃 기준

전체 화면을 3개 영역으로 분할. 기준 해상도 **1280×800** (LG 그램 14 / 1920×1200 @150%), 브라우저 배율 100%.

| 영역 | 크기 | 구성 |
|---|---|---|
| 상단 바 | 높이 56px 고정 | 1-1 큐레이션 정보 · 1-2 댓글 숨김 해제 · 1-5 닫기 |
| 미디어 스테이지 | 나머지 전체. 좌우 여백 92px(1-7 화살표 자리), 상하 여백 14px | 1-13 미디어 · 1-14 · 1-15 · 1-16 · 1-17 · 1-18 |
| 우측 정보 레일 | 폭 320px 고정 | **3단 구조** — [고정 헤더] 1-3 작성자 정보 · 1-4 더보기 / [스크롤] 1-6 본문 → 댓글 수 → 1-7~1-9 댓글 목록 / [고정 푸터] 1-10 고정핀 · 1-11 챌린지 상세 보기 |

**정보 레일 3단 구조 정책** : 본문(최대 500자)과 댓글이 많아도 **레일 내부에서만 스크롤**되고 미디어 영역은 고정. 작성자와 주요 액션은 스크롤 위치와 무관하게 항상 접근 가능해야 하고, 글 때문에 크게 보던 작품이 밀려나지 않아야 함
예외 처리 : 게시물 전환 시 레일 스크롤 위치는 최상단으로 초기화 / 댓글 0건이면 댓글 수만 표시(`댓글 0`), 목록 영역 미출력

- 미디어 가용 폭 = `100vw − 320 − 184` → 1280px에서 **776px**
- 미디어 가용 높이 = `100dvh − 56 − 28` → 800px에서 **716px** (미디어 2장 이상이면 1-15·1-16 컨트롤 44px을 뺀 **672px**)

정책 : 배율 축소·F11 등 사용자의 우회 조작을 전제하지 않음. 기준 해상도·배율 100%에서 모든 UI가 잘림 없이 표시되어야 함

## 1-1) 큐레이션 정보 (breadcrumb)

위치를 전체 화면 상단 바 좌측으로 이동하고, **각 항목을 클릭 가능하도록 변경**. 출력 규칙(3가지 케이스)은 기존과 동일.

`아하오호 갤러리 > {큐레이션명} > {챌린지명}`

| 케이스 | 출력 |
|---|---|
| 큐레이션 챌린지 게시물 | `아하오호 갤러리 > {큐레이션명} > {챌린지명}` |
| (자율창작) 챌린지 게시물 | `아하오호 갤러리 > {챌린지명}` — 큐레이션명 미출력 |
| (자율창작) 나만의 프로젝트 | `아하오호 갤러리` — 큐레이션 정보 미출력 |

- 아하오호 갤러리 → 상세보기 닫고 큐레이션 갤러리 화면으로 복귀
- {큐레이션명} → 해당 큐레이션 화면으로 이동
- {챌린지명} → 챌린지 상세 보기 모달 출력

정책 : 전체 화면은 현재 위치를 알려주는 단서가 모달보다 약하므로, 경로를 표시하고 상위로 되돌아갈 수 있게 함
예외 처리 : 큐레이션·챌린지 정보가 없는 케이스는 해당 구분자(`>`)도 함께 미출력

## 1-2) 숨겨진 댓글 숨김 해제 버튼 (unhide_comments)

위치를 상단 바 우측으로 이동. 노출 조건과 동작은 기존과 동일하되 아래를 명확히 함.

- 노출 조건 : **관리자가 숨긴 댓글**이 해당 게시물에 1건 이상 있을 때만 (작성자가 숨긴 댓글은 대상 아님 — 1-8 참조)
- 클릭 시 : 해당 게시물의 관리자 숨김 댓글을 **일괄 복원**
- 복원 후 : 숨겨진 댓글이 없으므로 **버튼도 미노출**로 전환

정책 : 되돌리기(재숨김)는 이 버튼이 아닌 1-9-1 댓글 숨기기로 수행. 버튼이 토글로 남아 있으면 현재 상태를 오해할 수 있어 단방향으로 처리

## 1-5) 게시물 상세보기 닫기 버튼 (close)

모달 외부 우측 상단 → **상단 바 우측 끝**으로 이동. 상단 바 좌측 끝에 `←`(뒤로) 버튼을 함께 배치.
`ESC` 키로도 닫힘.

## 1-7) 다음·이전 게시물 이동 화살표 (post_nav)

모달 외부 → **미디어 스테이지 좌우**로 이동. 크기 **64px 원형** + 하단 라벨(`이전 작품` / `다음 작품`).
키보드 `←` `→` 로도 이동.

- 이동 규칙은 기존과 동일 : 같은 큐레이션 내 다음 게시물로 이동, 큐레이션 내 마지막 게시물이면 다음 큐레이션의 첫 번째 게시물로 이동
- 첫 게시물에서 `이전`, 마지막에서 `다음`은 비활성 처리

정책 : 교사가 학급 작품을 연속으로 확인하는 것이 이 화면에서 가장 빈번한 조작이므로, 미디어 내부 조작(1-15)보다 크고 눈에 띄는 위치에 배치
예외 처리 : 게시물 전환 시 1-17 확대 배율은 1배로 초기화

## 1-6) 게시물 내용 (post_body) — 폰트 크기 변경

출력 규칙(작성자가 입력한 프로젝트 설명, 최대 500자)은 기존과 동일. **폰트 크기만 상향**한다.

- 본문 : `16px / weight 600` (댓글 본문은 `13px / weight 400` 유지)

정책 : 전체 화면 전환으로 레일 폭이 확보되었고, 아이가 쓴 설명은 교사가 실제로 읽는 콘텐츠임. 댓글과 같은 크기로 두면 본문이 목록에 묻혀 위계가 드러나지 않으므로 본문을 크게 하고 댓글은 그대로 두어 구분
예외 처리 : 500자를 채워도 1-18 레일 내부에서만 스크롤되고 미디어 크기에는 영향 없음

## 1-8) 댓글 내용 (comment_body)

기존 기획서 내용 그대로 유지. 전체 화면 전환으로 인한 변경 없음.

아래는 **1-2 숨김 해제 버튼의 대상 범위**를 개발 시 혼동하지 않도록 정리한 참조 표. 숨김의 주체가 다른 별개 항목임.

| 숨긴 주체 | 근거 항목 | 목록 표시 | 1-2 숨김 해제 대상 |
|---|---|---|---|
| **게시물 작성자(아이)가 앱에서 숨김** | 1-8 | 표시됨 — 내용 대신 「🙂 게시물 작성자에 의해 숨겨진 댓글이에요.」 출력 | ❌ 아님 (내용 복원 불가) |
| **관리자(교사)가 뮤지엄에서 숨김** | 1-9-1 | 목록에서 제외 | ✅ 일괄 복원 |

나머지 내용(전문 노출, 글자 수 무관)은 기존과 동일

## 1-10) 게시물 고정 상태 표시 (pin)

우측 패널 하단 → **정보 레일 하단 고정 바 좌측**으로 이동. 고정 정책(운영자 로컬 state, 서버 미저장, 해제 시 `createdAt DESC` 복귀)은 기존과 동일.

## 1-11) 챌린지 상세 보기 버튼 (challenge_detail)

우측 패널 하단 → **정보 레일 하단 고정 바 우측**으로 이동. 동작은 기존과 동일.

- 1-1의 {챌린지명} 클릭과 이동 대상이 동일(챌린지 상세 보기 모달) — **중복 경로를 의도적으로 유지**
- (자율창작) 나만의 프로젝트에서는 연결된 챌린지가 없으므로 미노출

## 1-13) 게시물 이미지/영상 (media) — 핵심 변경

**4:5 고정 비율 → 원본 비율 유지 + 미디어 스테이지 영역 맞춤(contain)** 으로 변경.

- 세로형·가로형·정방형·영상 모두 **비율을 유지한 채** 가용 영역 안에서 최대 크기로 표시
- **원본 해상도보다 크게 확대하지 않음** — 업스케일로 화질이 떨어지는 대신, 더 크게 볼 때는 1-17 확대 기능을 사용
- 영상도 이미지와 동일한 규칙으로 영역 맞춤

정책 : "이미지·영상이 작게 보인다"는 VOC의 직접 원인이 4:5 고정 크롭·축소였음. 작품을 원본 그대로 최대 크기로 보여주는 것이 이 화면의 목적
예외 처리 : `mediaUrl` 로딩 실패 시 기본 플레이스홀더 이미지 표시(기존 규칙 유지) / 잘못된 `mediaType`은 무시(image·video만 지원)

## 1-14) 영상 길이 표기 (duration)

**미디어 좌상단**에 고정 배치. 출력 규칙(`분:초`, 15초 이하 영상만 업로드 가능)은 기존과 동일.
1-17 확대 시 **함께 확대되지 않음**.

## 1-15) 동일 게시물 내 미디어 이동 화살표 (media_nav)

미디어 **내부** → 미디어 **바깥 하단**으로 이동. 1-16 인디케이터와 한 묶음(`◀ ● ● ▶`, 높이 44px)으로 배치.
노출 조건은 기존과 동일 : `uploadFiles.length > 1`

정책 : 이미지 위에 겹치면 작품 일부를 가리고, 확대 시 함께 커져 조작을 방해함. 이미지 밖으로 빼서 확대와 무관하게 항상 같은 크기·위치를 유지

## 1-16) 페이지 인디케이터 (media_indicator)

1-15와 한 묶음으로 미디어 바깥 하단에 배치. 현재 인덱스 표시(`● ○ ○`), 각 점 클릭으로 해당 미디어로 직접 이동.
노출 조건은 기존과 동일 : `uploadFiles.length > 1`

## 1-17) 미디어 확대 (zoom) — 신규

미디어를 커서 위치 기준으로 확대·축소.

- 입력 : 마우스 휠 또는 트랙패드 핀치(`ctrl + wheel`). **호버만으로는 동작하지 않음**
- 배율 : 1배 ~ 3배 (1배 미만 축소 없음)
- 이동 : 확대 상태에서 드래그(팬). 커서는 `grab`/`grabbing`
- 초기화 : 더블클릭, 게시물 전환, 상세보기 닫기
- 확대 대상은 **이미지·영상 자체로 한정** — 1-14 영상 길이, 1-15·1-16 컨트롤, 1-7 화살표, 1-18 조작 안내는 함께 확대되지 않음

정책 : 원본보다 확대하지 않는 1-13 규칙 때문에 원본이 작은 작품은 여백이 남을 수 있음. 이때 강제로 늘려 화질을 떨어뜨리는 대신, 필요한 사람만 필요한 부분을 확대해 보게 함
예외 처리 : 영상 재생 중에도 확대·이동 가능(재생 중단 없음) / 영상은 **하단 컨트롤 영역(약 48px)에서만 드래그 시작을 제외**하고 그 밖의 영역은 이미지와 동일하게 이동 — 재생바 조작과 충돌만 막고 이동은 가능해야 함

## 1-18) 조작 안내 (controls_hint) — 신규

미디어 스테이지 **좌하단**에 조작 방법을 아이콘과 함께 상시 노출. **항목별로 한 줄씩 세로 나열**.

| 순서 | 아이콘 | 문구 |
|---|---|---|
| 1 | 🔍 돋보기+ | 휠·핀치로 확대 |
| 2 | ✥ 사방 화살표 | 드래그로 이동 |
| 3 | 커서 | 더블클릭하면 원래 크기 |
| 4 | `←` `→` 키캡 | 작품 넘기기 |
| 5 | `ESC` 키캡 | 닫기 |

- 반투명 딤 배경의 둥근 사각 박스, 항목 간 8px 간격의 **세로 목록**. 확대 시 **함께 커지지 않음**
- 아이콘은 선(line) 스타일 단색, 키보드 조작은 키캡 형태로 표기해 "누르는 조작"임을 구분
- 가로 1줄로 나열하면 문구가 이어져 읽혀 개별 조작으로 구분되지 않으므로 세로 나열

정책 : 확대(1-17)와 키보드 이동은 화면에 단서가 없으면 발견할 수 없는 기능임. 교사가 매번 같은 사람이 아니고 수업 중에 사용법을 찾아볼 여유가 없으므로 상시 노출로 두되, 작품을 가리지 않는 좌하단에 저채도로 배치
예외 처리 : [작성 필요 — 문구 UX 라이팅 확정 / 아이콘 최종 에셋 확정]

## 인수 기준 (QA 확인 항목)

1. 기준 해상도 1280×800 · 브라우저 배율 **100%** · F11 미사용 상태에서 모든 UI가 잘림 없이 표시
2. 게시물 클릭 시 새 창·새 탭이 열리지 않음
3. 세로형·가로형·정방형·영상 4가지 비율에서 미디어가 가용 영역에 맞춰 최대 크기로 표시되고, 원본 해상도를 초과해 확대되지 않음
4. 창 크기를 변경해도 미디어가 잘리지 않고 비율을 유지한 채 축소·확대됨
5. 본문 500자 + 댓글 20건 상태에서 미디어 크기가 변하지 않고 레일만 스크롤됨
6. 확대 3배 상태에서 1-7·1-14·1-15·1-16·1-18의 크기·위치가 변하지 않음
7. 게시물 전환 시 확대 배율·레일 스크롤이 초기화됨
8. 1-2 버튼이 관리자 숨김 댓글이 있을 때만 노출되고, 복원 후 사라짐
9. 작성자가 앱에서 숨긴 댓글은 안내 문구로 표시되고, 1-2 복원 후에도 내용이 노출되지 않음
10. 영상 확대 상태에서 상단·중앙 영역 드래그로 이동되고, 하단 컨트롤 조작은 정상 동작
